## Original, working bridge details

- Source location on the tested host: `/home/royed/.local/share/kinect-v2-webcam/bridge.cpp` (source copied into this fork as `tools/kinect-v4l2-bridge/kinect-v4l2-bridge.cpp`).
- Running executable: `/home/royed/.local/bin/kinect-v2-bridge /dev/video10`.
- User service: `kinect-v2-webcam.service`, **enabled and active** at the time of inspection.
- Unit uses `KINECT_RESOLUTION=720p`, `LIBFREENECT2_PIPELINE=cpu`, `Restart=on-failure`, `RestartSec=15`.
- Process memory in inspected service status: approximately **56.8 MiB**.
- The old executable's **RUNPATH**: `/home/royed/libfreenect2/build/lib`; `ldd` resolved `libfreenect2.so.0.2` there. The old deployment therefore did **not** rely on a pkg-config-installed libfreenect2.
- `pkg-config --modversion freenect2` returned **Package freenect2 not found**. This does not mean the *running* original bridge lacked its library.
- JPEG decoding logs showed about 9 ms per image (around 110 decodes/s). This was **not** the observed video frame rate.

## Teams-for-Linux acceptance result

A video session in Teams-for-Linux visibly displayed a **live Kinect video image**. The bridge was running without a Protonect preview window or OBS Studio. The user reported the picture looked good. This verifies the basic camera-to-Teams integration **on this machine**, but does not establish that all clients, resolutions, RGB colour-chart accuracy, microphone devices, long calls, or every Teams version work.

## Independent reproduction test checklist

1. Record Debian version, kernel and whether matching headers are installed.
2. Run `lsusb -t`; verify Kinect on a `5000M` USB port.
3. Clone the fork to a clean folder and run `./scripts/install-kinect-v2-webcam.sh --no-start`.
4. Re-login after adding the `video` group; reboot if `v4l2loopback` was loaded before configuration.
5. Check `ldd ~/.local/bin/kinect-v2-bridge` and its `readelf -d` RUNPATH resolve only to expected local paths.
6. Start `systemctl --user enable --now kinect-v2-webcam.service` and inspect `journalctl`.
7. Test `v4l2-ctl` streaming and `ffplay` graphical preview.
8. In Teams-for-Linux, select `Microsoft Kinect v2` and check the live preview.
9. Note differences and actual fixes, then update `docs/V4L2_KINECT_BRIDGE.md` and this record.

For full installation steps, see [V4L2_KINECT_BRIDGE.md](V4L2_KINECT_BRIDGE.md).
